# TM 교체·공용 저장 수정 및 검증 보고서

검증일: 2026-09-10. 운영 전환은 아직 완료하지 않았습니다.

## 확인된 원인

1. 기존 신규교체 처리에서 취거품의 `isSpare`가 `false`가 되어 예비품 목록에서 제외되었습니다. 불용은 `flatMap`과 Firestore 삭제로 물리 부품 객체를 제거했습니다.
2. 편성 상세창은 취부 이력에도 교체작업의 고장유형을 표시했습니다. 리스크의 불확실성 검사도 취부품에게 상대 부품의 고장자료 누락을 연결했습니다. 개인 심각도 누적 T점수 자체는 기존에도 취거 시리얼 기준이었습니다.
3. `AppContext`가 localStorage를 초기값 및 상시 저장소로 사용하고 Firebase 미설정 시 기본 엑셀을 브라우저마다 자동 생성했습니다. 운영 URL에서도 로컬 데모 배너가 확인되었습니다.
4. 저장 성공 전 React 상태를 바꾸고 Firebase 미연결 저장 함수는 조용히 반환했습니다. 엑셀·복구는 컬렉션 삭제 후 전체 재작성, 교체는 서버 상태를 읽지 않는 트랜잭션과 전체 리스크 재저장을 사용했습니다.
5. 같은 위치 또는 TM_ID를 재사용한 다른 시리얼을 병합 과정에서 제거할 수 있었습니다.

기존 디자인과 주요 화면 배치는 유지했습니다. 기존 원본 엑셀은 보존했습니다. 작업 시작 전에 존재한 `assets/app.js` 변경은 원래 상태 그대로 별도로 남기며 커밋에 포함하지 않습니다. 운영 설정 없는 검증 빌드로 기존 fallback 자산을 교체하지 않습니다.

## 저장 구조

- 운영 기준: 기존 `tm_master/{serialNo}`, `replacement_history/{replacementId}`, `settings/risk`, `severity_master/{failureType}` 유지.
- 공용 변경 리비전: `system/state`. 모든 운영 변경은 리비전·감사기록과 함께 커밋합니다.
- 실시간 처리: `onSnapshot(system/state)`를 받아 서버 자료를 읽고 조회 전후 리비전이 같은 완전한 상태만 표시합니다.
- 백업: `backups`, `data_snapshots`의 완료 메타데이터 + `chunks` 하위 문서. 기존 단일 문서 백업도 읽습니다.
- 리스크: Firebase 원본 이력·설정으로 계산합니다. 기존 `risk_score` 문서는 삭제하지 않지만 신규 화면의 기준으로 읽거나 전체 덮어쓰지 않습니다. 제조군 통계 F 산식은 유지하고 개인 고장이력/T점수와 불확실성만 취거품에 귀속합니다.
- 초기자료: TM 샘플 자동 생성 없음. 기본 설정은 최초 저장 시 없을 때만 기록. 이미 초기화한 빈 심각도 목록도 기본값으로 재생성하지 않습니다.
- PC 자료: 자동 삭제·자동 합치기 없음. 관리자 이관 기능은 원본을 보존하고 빈 공용 DB에만 반영합니다. 여러 PC 자료나 과거 소실 ID는 확인된 백업 없이 추측 복원하지 않습니다.
